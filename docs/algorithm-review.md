# 健身计划算法审查与修正

审查日期：2026-10-25。范围：动作库、计划生成器、分化选择、训练量展示、锁定与替换、记录后的进阶建议。

## 判断

旧版可以稳定执行规则，但不能据此认为训练处方可靠。它是使用手工系数的确定性贪心算法，没有个体数据拟合，没有证明整体最优，也没有训练效果试验。修正后的版本改善了可检查的排程约束，并明确保留了同样的效果验证边界。

“数学算得出来”“软件约束正确”“训练原则有研究支持”“对这个人有效”是四件不同的事。当前能检查前两项，部分原则有研究依据，最后一项仍需真实训练与反馈。

## 原来的问题及原因

| 问题 | 原实现 | 影响与修正 |
| --- | --- | --- |
| 分化不符合部位集中的需求 | 1–3 练一律全身；4 练一律上下肢 | 这两种模式本身有效，但不等于部位分化。增加显式分化选择，默认部位分化。 |
| 当天没有完整的安排目标 | 全周所有动作一起按缺口评分，没有当天基础动作槽位 | 可能补齐小肌群分数，却漏掉当天重要动作。先安排当天基础动作，再分配剩余时间。 |
| 放行条件过宽 | primary 中任一肌群属于当天即可；核心同时出现在多个分化日 | 现在按最大主目标系数所对应的主导部位筛选。辅助参与不能让动作跨越分化边界。 |
| 部位预算重复 | 上胸、中胸、下胸各自得到完整基准量 | 胸部合并一个预算，背部同理；每个工作组对同一组别最多折算为 1 组。区域偏好仍影响选动作。 |
| 伪精确参数 | 基准组数 × 偏好 × growth × recoverySupport；按肌群固定 36–66 小时恢复 | 没有看到参数来源或校准数据。移除增长补偿与按肌群精确恢复的说法；48 小时仅作为统一排程参考。 |
| 加组与评分不一致 | 新动作常加 2–3 组，但超量处罚固定按 2 组预测；加 1 组仍用相同评分 | 现在根据实际待加组数计算边际缺口收益。 |
| 锁定可能失效 | 原填充阶段仍能修改锁定动作组数；切换分化未检查锁定兼容性 | 兼容锁定保持组数，不参加自动加组；不兼容时移除并说明；超时保留且提示。 |
| 替换、编辑与旧数据边界 | 替换未限制当天部位，提示可能过期；旧计划不会随代码升级自动变化 | 替换检查分化并排除重复动作；当前提示重新计算；旧计划提示用户重新生成，历史记录保留。 |
| “有效量”容易被当成效果 | 百分比没有区分规则覆盖与生理效果 | 改称估算预算，展示主导动作组数与频次；明确百分比不预测增肌。 |

原默认 4 练的上肢日混有胸、背、肩，符合“上肢训练”的定义，并不单凭这一点构成训练学错误。问题是它没有让用户选择更集中的分化，也没有保证各部位在当天的安排结构。

## 当前如何生成

1. 根据器械、把手和动作排除设置筛选动作与可用版本。
2. 读取选定星期与分化；以实际星期数量为准。
3. 在这些星期上比较分化顺序，尽量减少不足 48 小时的相关部位重叠，包含周日到下周一。
4. 保留与当天部位、器械和排除设置兼容的锁定动作。
5. 为每个训练日的基础动作类型先安排至少 2 个工作组，可用时优先复合动作。未完成的槽位显示具体原因。这是模板最低安排，不能解释为“练够”。
6. 在所有训练日间比较补量候选，根据全周缺口与当天缺口逐步增加组数。动作必须属于当天，预计时间不得超过预算。
7. 复合动作排在孤立动作之前，生成训练量估算与缺口、低频和负荷重叠提示。

默认部位分化：

| 每周次数 | 模板 |
| --- | --- |
| 1 | 全身 |
| 2 | 上肢、下肢＋核心 |
| 3 | 推、拉、腿＋核心 |
| 4 | 胸＋三头、背＋二头、腿＋核心、肩 |
| 5 | 胸、背、腿＋核心、肩、手臂＋核心 |
| 6 | 推、拉、腿＋核心，两轮 |

可以显式选择上下肢交替或全身训练。部位分化在低频时可能导致大肌群每周主导训练仅一次，界面会提示；不能同时承诺部位高度集中、很短的单次时长、很高的周频次和足够的全身训练量。

## 数学规则的含义与局限

起始预算为 `训练水平基准（6 / 8 / 10） × 偏好因子`。胸部与背部取对应区域预算的平均值，不把区域预算相加。6、8、10 的具体分档及偏好倍数是产品起点，训练年限不足以推算个人最佳量。

动作库仍用主次肌群系数估算参与量。组别系数为对应区域系数之和，上限为 1；组别周量为各动作 `组数 × 组别系数` 的和。最大主目标系数对应的部位用于判定主导目标，主导组数另行统计。其余参与量不能直接解释为同等有效的工作组。

补量分数计算：

- 全周收益：每肌群 `min(剩余周预算, 本次折算量) / 周预算`，再求和。
- 当天收益：每个主导肌群 `2 × min(当天剩余预算, 本次组数) / 当天预算`，再求和。
- 用区域偏好调整；相邻日主导部位重叠时乘以 0.7，同类重复动作乘以 0.8。
- 除以估算增加的时间，比较每分钟收益。

这些权重是可审查的启发式选择，没有来自训练效果的参数拟合。贪心分配没有整体最优保证。

自动安排每动作最多 4 组、每肌群单日最多 10 个主导动作组，是控制单次堆量的产品约束，不能当作生理极限。兼容的用户锁定组数优先保留；超时不会继续自动填充。

时长按热身预留 8 分钟、每工作组约 45 秒加对应休息、每动作转换约 1.2 分钟估计并取整。单侧动作耗时、器械排队和额外热身没有个体建模，实际用时可能超过估算。

## 研究支持到什么程度

- [Ramos-Campo 等，2024，分化与全身训练系统综述](https://pubmed.ncbi.nlm.nih.gov/38595233/)：等训练量时，没有发现两类安排对力量和增肌的显著差异。支持按偏好和安排选择分化，不支持“全身训练是错误的”。
- [ACSM，2026，抗阻训练指南官方解读](https://acsm.org/resistance-training-guidelines-update-2026/)：增肌可参考每肌群每周约 10 组，训练应个体化，普遍要求每组力竭没有必要。这不是每个人必须凑够的阈值，也没有验证本项目的分档与系数。
- [Pelland 等，2026，训练量与频次剂量反应分析](https://pubmed.ncbi.nlm.nih.gov/41343037/)：区分直接与间接组数有解释价值，训练量收益存在递减。不能据此证明动作库中的 0.17、0.55 等具体系数准确。
- [Refalo 等，2024，力竭与保留余力训练研究](https://pubmed.ncbi.nlm.nih.gov/38393985/)：在该研究人群与条件下，保留余力也可获得增肌效果，力竭组疲劳更高。不能推广为所有人的固定最佳 RIR。

## 尚未解决的效果验证

- 无真实训练干预、个体恢复模型、预测误差测量或教练系统评审。
- 动作版本共用组数、次数范围、休息和加重幅度；具体器械的重量步长、辅助重量方向和动作差异仍需人工判断。
- 重量选择依赖用户输入；填写过重量不等于当前仍适合。RIR 依赖真实、准确的自我估计。
- 记录可以给出双进阶建议，但没有依据历史自动调整周训练量。睡眠、饮食、疼痛、依从性与实际动作质量未纳入生成器。
- 单日主导组数与折算组数只是两个记账视角，不能判断一组是否足够接近力竭或动作是否规范。

下一步应先让合格训练人员审阅不同器械与训练水平的样例，再以实际完成率、真实用时、重量和次数趋势、疲劳与不适反馈持续调整。要声称算法优于常规模板，需要预先定义比较目标、对照方案与训练效果指标，并开展独立验证。

## 本次验证

- `npm test`：19 项测试，包括 216 种频次、分化、时长与器械组合；检查分化、时间、动作版本、重复、组数、锁定冲突、恢复跨周和不完整进阶记录。
- `npm run build`：生产构建。
- `node tests/browser-smoke.mjs`：分化选择、训练量展示、器械、锁定与替换弹窗、训练保存、规则说明、移动端和旧计划升级。

这些是软件行为验证，不是训练效果验证。
