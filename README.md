# SET

<img src="public/favicon.svg" width="56" height="56" alt="SET" />

本地运行的力量训练计划与记录工具。

SET 根据可用器械、训练分化、时间安排和肌群偏好生成计划，支持手动编辑、版本管理与逐组训练记录。计划、个人资料和训练历史保存在本机 SQLite 数据库中。

## 主要功能

| 功能 | 说明 |
| --- | --- |
| 训练计划生成 | 支持每周 1–7 练，提供部位分化、上下肢、全身及自定义分化，可指定每个训练日的肌群。 |
| 器械与动作选择 | 根据实际拥有的器械和配件筛选动作，区分不同器械版本的处方及区域肌群参数。 |
| 计划编辑 | 拖拽调整顺序，编辑组数、重量、目标次数与休息，替换或删除动作；预计用时随编辑更新。 |
| 计划与版本管理 | 新建、复制、重命名、切换和恢复计划；为版本命名或添加备注，预览并恢复历史内容。 |
| 训练记录 | 分别记录热身组和工作组的重量、次数、RIR，查看完成量、负荷匹配情况与进阶建议。 |
| 每周训练量 | 汇总肌群周目标、预计量与实际完成量，查看贡献动作；根据多周记录提供调整建议，由用户应用。 |
| 自定义动作 | 添加器械与动作、配置肌群参与和负重方式；删除自定义动作后保留已有计划和记录中的历史内容。 |
| 本地数据与 Docs | SQLite 自动保存，支持 JSON 备份和旧数据迁移；集中说明各项输入的作用及算法规则。 |

## 快速开始

需要 **Node.js 22.13 或更高版本**及 npm，建议使用 Node.js 24。无需另行安装数据库服务。

下载或克隆仓库后，在项目根目录执行：

```sh
npm ci
npm run dev
```

在浏览器打开 **http://127.0.0.1:5173**。首次打开时会创建数据库，并载入初始计划或迁移旧数据。

日常使用也可以先构建，再启动构建版：

```sh
npm run build
npm start
```

开发版与构建版使用相同的默认数据库和端口。代码更新后，构建版需要重新执行 `npm run build`。

服务默认只监听本机，端口被占用时停止启动，不会自动改用其他端口。在终端按 `Ctrl+C` 可以停止服务；数据文件仍然保留，下次启动后继续使用。

## 使用流程

1. 在“我的健身房”中选择可用器械与配件。
2. 在“训练参数”中设置训练星期、分化、单次时长、肌群偏好、体重和当前工作重量。
3. 在“本周计划”中生成安排，按需要编辑动作、顺序、组数、次数及休息。
4. 保存计划版本并填写名称，保留调整前后的内容。
5. 开始训练，逐组填写实际数据，完成后保存训练记录。
6. 查看每周训练量与进阶建议，再决定是否应用调整。

编辑当前计划会自动保存草稿；“保存版本”会额外建立可恢复的快照。修改训练参数后，需要重新生成才能重新分配动作。导入备份会以备份内容恢复应用数据，不会逐条合并现有内容。

## 数据保存

### 内置 SQLite

```text
浏览器界面 → 本机 /api/state 接口 → Node.js 内置 SQLite → data/set.sqlite
```

数据库引擎由 Node.js 的 `node:sqlite` 模块提供。启动项目即可使用，不需要数据库账号、连接字符串或独立数据库进程。

保存范围包括：

- 全部计划、当前草稿与历史版本。
- 训练参数、体重、肌群和区域偏好。
- 实际训练记录、动作快照与恢复反馈。
- 器械、配件及自定义动作。

完整应用状态以 JSON 快照存入 SQLite 的 `app_state` 表，一次更新原子写入。数据库修订号用于防止旧页面覆盖新数据，与用户保存的计划版本编号分别管理。

关闭服务、重启电脑或清除浏览器缓存不会删除已写入的 SQLite 数据。同一数据库下的不同浏览器共享数据；当前项目按本地单用户使用设计，没有账号隔离或跨设备自动同步。

浏览器保留兼容缓存和待保存修改。写入失败时，页面会提供重试或导出；发生多页面冲突时，可以先导出当前修改，再读取数据库中的新版本。

### 自定义数据库位置

默认路径为项目根目录下的 `data/set.sqlite`。环境变量 `SET_DATABASE_PATH` 可以指定其他文件位置，相对路径按项目根目录解析。

macOS / Linux：

```sh
SET_DATABASE_PATH=/path/to/set.sqlite npm start
```

PowerShell：

```powershell
$env:SET_DATABASE_PATH = "C:\SET-data\set.sqlite"
npm start
```

开发版同样支持该环境变量，将命令替换为 `npm run dev` 即可。改变路径相当于打开另一个数据库文件，不会自动移动原有数据。

### 从旧版本迁移

数据库为空时，首次打开页面会将当前浏览器中的旧数据迁移至 SQLite。请使用原来保存计划的**同一浏览器与访问地址**完成这一步；例如 `localhost` 与 `127.0.0.1` 对应的旧浏览器存储不同。

首次连接前的浏览器数据会另行保留，可在应用 Docs 的“计划、版本与数据保存”中点击“导出迁移前浏览器备份”。数据库已有内容时，以数据库为准，不会被另一浏览器的旧缓存覆盖。

如果原浏览器或地址已经改变，可使用旧版本导出的 JSON，通过应用的“导入”功能恢复。

## 备份与源码发布

日常备份使用应用中的“导出备份”，JSON 包含所有计划、版本、资料、记录和自定义内容。换电脑后可以通过“导入”恢复。

也可以复制数据库进行备份：先停止服务，再复制整个 `data` 目录。SQLite 运行时可能生成 `-wal` 和 `-shm` 文件，不应在服务运行期间仅复制主数据库文件。

以下内容已被 `.gitignore` 排除：

| 内容 | 忽略规则 |
| --- | --- |
| 默认数据库目录 | `data/` |
| SQLite 文件及其日志 | `*.sqlite`、`*.sqlite-*` |
| 导出的个人备份 | `SET-backup-*.json`、`形训备份-*.json` |
| 依赖、构建及测试产物 | `node_modules/`、`dist/`、`artifacts/` |
| 本地环境文件 | `.env`、`.env.*`，保留 `.env.example` |

源码与个人数据分别保存。当前 SQLite 功能需要本机 Node.js 服务，单独将 `dist/` 上传到静态托管无法提供数据库接口。

## 算法与指标

计划生成使用基于规则的启发式算法：先检查器械条件及当天允许肌群，再安排基础动作，按周目标缺口、偏好和时间预算分配动作与组数。

周目标百分比表示折算工作组相对于预算的比例，100% 代表达到预算。区域参与系数用于估算训练量；它们不等同于实测发力比例。完成工作组、次数达成和负荷匹配分别统计，超过目标次数或余力较多不会被直接记为未完成。

进阶与训练量调整使用实际记录和恢复反馈，建议由用户决定是否应用。自动测试验证软件行为符合规则，不代表已验证长期训练效果。

各输入的作用、分化规则、时长公式、组数折算和进阶条件，以应用中的 **Docs** 为主要说明。相关实现文档：

- [计划与版本管理](docs/plan-management.md)
- [算法审查与边界](docs/algorithm-review.md)
- [肌群模型核查](docs/muscle-audit.md)
